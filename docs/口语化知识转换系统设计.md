## 1. 概述

### 1.1 背景

企业在部署语音客服机器人时，通常已积累大量**文本知识库**（产品参数 FAQ、活动话术、售后服务政策等）。这些材料面向「阅读」场景编写，与语音机器人的播报要求存在本质差异：

| 维度 | 文本知识库 | 语音机器人知识库 |
|------|-----------|----------------|
| 呈现方式 | HTML 富文本，可跳转、可回看 | 纯语音播报，听一遍就要懂 |
| 知识粒度 | 整份文档作为一条知识 | 一问一答，意图原子化 |
| 语言风格 | 书面语、术语密集 | 口语化，数字逐字读 |
| 答案结构 | 多型号/多参数并列 | 按实体拆分，单独播报 |
| 触发语 | 往往缺失 | 需要大量口语相似问 |

**典型失败场景**：某出行设备企业将 28 条知识导入下游语音平台，全部因「答案长度超出 30,000 字符上限」失败。根因是将整份产品参数 FAQ（含 40+ 子问题、近万字 HTML）当作一条知识写入，而非拆分为可播报的原子问答。

### 1.2 目标

构建 **口语化知识转换工具**，完成以下链路：

```
文本/HTML 知识原件  →  语音化原子问答  →  下游平台 xlsx 导入文件
```

### 1.3 核心能力

| # | 能力 | 说明 |
|---|------|------|
| 1 | 文档拆解 | 文档级 → 问答级（1 个编号子问题 = 1 条知识） |
| 2 | 多实体拆分 | 多型号并列答案 → 按型号独立条目 |
| 3 | 口语化改写 | HTML 清洗 + 数字规范化 + 控长 + 多轮答案 |
| 4 | 相似问生成 | 每条知识生成 5–8 条口语触发语 |
| 5 | 去重审核 | 语义去重、冲突检测、目录规范化 |
| 6 | 模板导出 | 严格对齐平台三 Sheet 导入格式，可直接上传 |

### 1.4 关键设计决策

| 决策项 | 结论 |
|--------|------|
| 与冷启动工具关系 | **独立模块**，不合并导出 |
| 答案默认字数上限 | **120 字**（可配置 50–500） |
| 超长答案处理 | 使用平台「多答案多行」机制，不使用「答案超限内容」列 |
| 品牌/行业规则 | 通过 `companyName` / `companyBrief` 动态注入，不写死在文档中 |
| 导出方式 | 克隆内置 xlsx 模板，保留表头与合并单元格 |

## 2. 系统定位

### 2.1 在 SmartCS 中的位置

```
SmartCS
├── [Tab 1] 对话冷启动分析     ← 已有：通话转写 → 场景 / SOP / FAQ
└── [Tab 2] 知识库语音化转换   ← 新增：文本知识库 → 平台导入文件
```

两个工具共用「品牌名称 / 业务背景」配置，但**数据流、历史记录、导出格式完全独立**。

### 2.2 能力对比

| 维度 | 对话冷启动 | 知识库语音化转换 |
|------|-----------|----------------|
| 输入 | 通话转写流水 | 静态文本 / HTML 知识库 |
| 核心任务 | 从对话中**挖掘**场景与流程 | 将已有知识**改写**为语音格式 |
| 输出 | Scenario + SOP + FAQ（JSON） | 平台 xlsx 三 Sheet |
| 是否合并 | 否 | 否 |

### 2.3 目标用户

- **语音客服运营**：上传知识库、审核转换结果、导出导入
- **知识库管理员**：维护目录结构、处理冲突与敏感条目

## 4. 输入与配置

### 4.1 支持的输入格式

| 格式 | 典型场景 | 处理方式 |
|------|----------|----------|
| `.xlsx` | 平台模板、导入失败回执 | 解析「问答知识」Sheet，跳过前 3 行表头 |
| `.xls` | 历史 Excel 原件 | 转换为 xlsx 后解析 |
| `.csv` | 已有 Q&A 表格 | 映射 question / answer / category 列 |
| `.txt` / `.md` | 政策、手册、FAQ 文档 | 全文分块后送入 LLM 提取 |

### 4.2 配置项定义

```typescript
interface KnowledgeTransformConfig {
  // ── 基础 ──
  companyName: string;               // 必填：企业/品牌名称（动态注入 Prompt）
  companyBrief?: string;             // 可选：业务背景描述
  docType: DocType;                  // 文档类型（见 4.3）

  // ── 语音化 ──
  maxAnswerLength: number;           // 单轮答案字数上限，默认 120（50–500）
  maxAnswerTurns: number;            // 多轮答案轮数上限，默认 5（最大 50）

  // ── 目录 ──
  categoryDepth: number;             // 目录层级，默认 2
  categoryPrefix?: string;           // 目录前缀，如 "语音客服/"

  // ── 相似问 ──
  generateSimilarQuestions: boolean; // 默认 true
  similarQuestionsPerEntry: number;  // 每条生成数量，默认 8
  generateRegexSimilar?: boolean;      // 是否生成正则相似问，默认 false

  // ── 平台标签列（K–M 列，可选）──
  defaultTags?: {
    audience?: string;               // 对内对外
    callModule?: string;             // 呼叫模块
    ticketModule?: string;           // 工单模块
  };

  // ── 关联问（P2）──
  knowledgeSubLibrary?: string;      // 知识子库名称
}

type DocType = 'param_faq' | 'activity' | 'service' | 'mixed';
```

### 4.3 文档类型与拆分策略

| docType | 适用内容 | 拆分策略 | 目录示例 |
|---------|----------|----------|----------|
| `param_faq` | 产品参数、规格 FAQ | 按编号子问题拆分 | `产品大类/Pro系列` |
| `activity` | 营销活动、发布会话术 | 按场景或子问题拆分 | `产品大类/营销活动` |
| `service` | 售后政策、权益说明 | 按权益项或流程步骤拆分 | `产品大类/增值服务` |
| `mixed` | 混合文档 | 自动识别后分路径处理 | 自动推断 |

### 4.4 配置默认值

| 配置项 | 默认值 |
|--------|--------|
| maxAnswerLength | 120 |
| maxAnswerTurns | 5 |
| categoryDepth | 2 |
| similarQuestionsPerEntry | 8 |
| generateSimilarQuestions | true |
| generateRegexSimilar | false |
| docType | mixed |

## 5. 数据模型

### 5.1 阶段数据流

```
原始文件
  → RawFinding[]          (Phase 1)
  → KnowledgeEntry[]      (Phase 2)
  → KnowledgeEntry[]      (Phase 3，去重后)
  → SimilarQuestionEntry[] (Phase 5)
  → KnowledgeTransformResult (最终)
  → xlsx 文件              (Phase 7)
```

### 5.2 RawFinding（Phase 1 输出）

```typescript
interface RawFinding {
  category: string;          // 一级分类
  subCategory?: string;      // 二级分类（系列/场景）
  docTitle?: string;         // 原文档标题（不作为标准问）
  question: string;          // 提取的用户问题
  answer: string;            // 原始答案（可含 HTML）
  keywords: string[];
  sourceExcerpt: string;     // 原文追溯片段
  isComplex: boolean;        // 是否敏感/复杂
}
```

### 5.3 KnowledgeEntry（Phase 2/3 输出）

```typescript
interface KnowledgeEntry {
  categoryPath: string;        // 目录路径，如 "产品大类/Pro系列"
  standardQuestion: string;    // 用户口语疑问句，≤200 字
  summary: string;             // 一句话摘要，≤50 字，供运营审核
  answerTurns: string[];       // 语音播报答案，每轮 ≤ maxAnswerLength
  keywords: string[];
  needsHuman: boolean;         // 是否需人工审核
  transferReason?: string;     // 转人工原因
  sourceExcerpt: string;       // 原文追溯（不导出）
  conflict?: boolean;          // Phase 3 标记：答案冲突
}
```

### 5.4 SimilarQuestionEntry（Phase 5 输出）

```typescript
interface SimilarQuestionEntry {
  categoryPath: string;
  standardQuestion: string;    // 必须与主表字符级完全一致
  type: '用户相似问' | '正则相似问';
  phrases: string[];
}
```

### 5.5 KnowledgeTransformResult（最终结果）

```typescript
interface KnowledgeTransformResult {
  companyName: string;
  entries: KnowledgeEntry[];
  similarQuestions: SimilarQuestionEntry[];
  audit: {
    removedCount: number;
    mergedCount: number;
    conflicts: Array<{
      standardQuestion: string;
      answers: string[];
      resolution?: string;
    }>;
  };
  stats: {
    totalSourceDocs: number;
    totalEntries: number;
    totalSimilarQuestions: number;
    humanRequiredCount: number;
    avgAnswerLength: number;
    multiTurnCount: number;
    processingTimeMs: number;
  };
  warnings: ExportWarning[];
}
```

### 5.6 进度回调

```typescript
interface KnowledgeTransformProgress {
  phase:
    | 'parsing'
    | 'extracting'
    | 'voiceifying'
    | 'deduplicating'
    | 'generating_similar'
    | 'exporting'
    | 'cooldown';
  currentChunk: number;
  totalChunks: number;
  message?: string;
  processedEntries?: number;
}
```

## 6. 处理流水线

### 6.1 全流程

```
上传原件
  │
  ├─ Phase 0  预处理          （本地规则，无 LLM）
  ├─ Phase 1  文档拆解提取     （deepseek-chat，JSON mode）
  ├─ Phase 2  语音化改写       （规则引擎 + deepseek-chat，批量）
  ├─ Phase 3  整合去重审核     （deepseek-reasoner）
  ├─ Phase 5  相似问生成       （deepseek-chat，批量）
  └─ Phase 7  映射导出         （克隆模板 + 本地校验）
  │
  ▼
下载 xlsx 导入文件
```

### 6.2 Phase 0：预处理

| 步骤 | 说明 |
|------|------|
| 文件解析 | 识别 xlsx / xls / csv / txt，xls 转 xlsx |
| 行定位 | 平台模板：第 1–3 行为表头，第 4 行起为数据 |
| 字段映射 | 所属目录、标准问、答案内容、失败原因等 |
| 文本分块 | 150 KB/块，总上限 1 MB |
| HTML 检测 | 判断答案是否含富文本标签 |
| 类型推断 | 「参数FAQ」→ param_faq；「话术」→ activity |
| 脏数据清洗 | 去除 `\| 品类名` 后缀；统一中英文标点 |

### 6.3 Phase 1：文档拆解提取

**目标**：「1 文档 = 1 知识」→「1 子问题 = 1 知识」

| 识别结构 | 规则 | 示例 |
|----------|------|------|
| 编号问答 | `1. xxx？` / `2、xxx？` | 参数 FAQ 内子问题 |
| 章节标题 | `<h2>一、基本信息</h2>` | 按章节边界切分 |
| 文档标题 | 标准问列的值 | 不作为标准问，归入目录/简介 |
| 多实体并列 | `A：xxx。B：yyy。` | 触发 Phase 2 前预拆分 |

**拆解示例**：

```
输入:
  标准问: 某系列参数FAQ | 产品线A
  答案:   [整份 HTML，约 9700 字纯文本]

输出 (~44 条 RawFinding):
  { question: "Pro系列标准版的认证型号是什么？", answer: "ABC800DQT-6A" }
  { question: "Pro系列有哪些颜色可选？", answer: "墨黑、珍珠白..." }
  ...
```

### 6.4 Phase 2：语音化改写

**处理链路**（每条答案）：

```
原始答案 (HTML/文本)
  │
  ├─ Layer 1 规则引擎（本地，确定性）
  │    HTML 剥离 → 标点统一 → 数字口语化 → 符号处理 → 硬控长
  │
  ├─ Layer 2 LLM 改写（语义性）
  │    句式口语化 → 标准问改写 → 语义断句 → 多轮拆分
  │
  └─ 输出 KnowledgeEntry
```

### 6.5 Phase 3：整合去重审核

| 动作 | 说明 |
|------|------|
| 语义去重 | 合并含义重复的标准问 |
| 目录规范化 | 统一同义目录名（如「售后」/「售后服务」） |
| 冲突检测 | 同一标准问存在不同答案 → `conflict: true` |
| 无效过滤 | 删除空问题、空答案、页码/目录行 |
| 标准问精简 | 超过 200 字自动压缩 |
| 统计输出 | 总数、需人工数、平均答案长度、多轮条数 |

### 6.6 Phase 5：相似问生成

- 每条标准问生成 N 条相似问（默认 8，可配置）
- 相似问更短、更口语（建议 ≤15 字）
- 覆盖简称、省略主语、口语疑问、ASR 常见变体
- 不引入答案中不存在的信息

### 6.7 Phase 7：映射导出

1. 克隆内置 `问答库导入模板.xlsx`（保留合并单元格与表头）
2. 写入「问答知识」Sheet（第 4 行起）
3. 写入「相似问」Sheet（第 3 行起）
4. 执行导出前校验（见第 10 章）
5. 生成可下载的 xlsx 文件

## 7. 文字处理规则

### 7.1 双层处理架构

```
┌─────────────────────────────────────────┐
│  Layer 1：规则引擎（本地，确定性）        │  格式、符号、数字
├─────────────────────────────────────────┤
│  Layer 2：LLM 改写（Prompt 驱动）        │  语气、句式、语义
└─────────────────────────────────────────┘
```

**原则**：能规则化的不用 LLM（稳定、省成本）；语义理解和句式润色交给 LLM。

### 7.2 Layer 1：规则引擎

#### HTML / 富文本清洗

| 操作 | 说明 |
|------|------|
| 剥离标签 | `<h2>` `<p>` `<span>` 等全部去除 |
| 实体解码 | `&nbsp;` `&amp;` 等转为字符 |
| 语义换行 | 标题标签结束处插入换行 |
| 列表处理 | `•` `-` `<li>` 转为口语连接 |
| 空白规整 | 连续空格/换行压缩 |

#### 标点与分隔符

| 规则 | 处理 |
|------|------|
| 英文标点 | `,` `.` `:` → `，` `。` `：` |
| 品类后缀 | `\| 产品线A` 等后缀删除 |
| 管道符 | 标准问中 `\|` 删除 |

#### 数字与单位口语化

| 类型 | 原文示例 | 语音化示例 |
|------|----------|-----------|
| 整数 | 104 | 一百零四 |
| 金额 | 299元 | 两百九十九元 |
| 重量 | 104kg | 一百零四公斤 |
| 功率 | 800W | 八百瓦 |
| 续航 | 85km | 八十五公里 |
| 尺寸 | 1590×710×1070mm | 长一米五九、宽七十一、高一米零七 |
| 日期 | 2026/6/9 | 二零二六年六月九日 |
| 型号 | ABC800DQT-6A | A B C 八零零 D Q T 杠六 A |
| 防水等级 | IPX7 | I P X 七 |
| 并列色名 | 墨黑/珍珠白/银色 | 墨黑、珍珠白和银色 |

#### 控长与多实体拆分

| 规则 | 说明 |
|------|------|
| 硬上限 | 默认 120 字，可配置 |
| 截断点 | 优先在 `。` `；` `，` 处断开 |
| 超长处理 | 写入 `answerTurns` 下一轮，非 G 列 |
| 多实体检测 | `标准版：xxx。联名款：yyy。` → 拆为多条 |

### 7.3 Layer 2：LLM 口语化规则

规则通过 Prompt 注入，分四组（代码见 `services/prompts/knowledgeTransformPrompts.ts`）。

#### 核心规则（20 条，每次必带）

| 分类 | 要点 |
|------|------|
| 语气人设 | 您/我们；专业简洁；避免绝对承诺 |
| 句式结构 | 先结论后解释；一句一意；并列 ≤3 项 |
| 信息密度 | 单条 1 个信息点；参数 ≤3 个数值；步骤 ≤3 步 |
| 指代规范 | 禁止该/此/上述/点击/查看/扫码 |

## 9. 下游平台导出映射

### 9.1 模板结构

平台标准导入模板 `问答库导入模板.xlsx` 含 3 个 Sheet：

| Sheet | 用途 | 数据起始行 | 优先级 |
|-------|------|-----------|--------|
| 问答知识 | 主表 | 第 4 行 | P0 必填 |
| 相似问 | 触发语扩展 | 第 3 行 | P0 强烈建议 |
| 关联问 | 关联推荐问 | 第 3 行 | P2 |

**硬性约束**：

- 第 1–3 行（说明 + 双行表头 + 标签列定义）不可删除
- 必须克隆模板（保留合并单元格），禁止新建空白 xlsx

### 9.2 问答知识 Sheet 字段映射

| 列 | 字段 | 写入值 | 备注 |
|----|------|--------|------|
| A | *所属目录 | categoryPath | 多级用 `/` 分隔 |
| B | *标准问 | standardQuestion | ≤200 字 |
| C | 简介类型 | `纯文本` | 固定 |
| D | 简介内容 | summary | ≤50 字 |
| E | 答案类型 | `纯文本` | 固定 |
| F | *答案内容 | answerTurns[0] | ≤ maxAnswerLength |
| G | 答案超限内容 | **留空** | 语音场景不使用 |
| H | 问答召回规则 | 留空 | |
| I–J | 生效时间 | 留空 | 立即生效且永久有效 |
| K–M | 知识标签 | defaultTags | 用户配置 |

**多轮答案**：`answerTurns[1..n]` 各占一行，仅修改 F 列，其余列与首行一致。

### 9.3 相似问 Sheet 字段映射

| 列 | 写入值 | 约束 |
|----|--------|------|
| A 标准问所属目录 | 与主表 categoryPath 一致 | |
| B 标准问 | 与主表 standardQuestion **字符级完全一致** | 强制 |
| C 相似问类型 | `用户相似问` | 默认 |
| D 相似问 | 每条 phrase 一行 | ≤200 字 |

### 9.4 超长答案策略

```
语音控长（默认 120 字）  ≠  平台字段上限（30,000 字）

语音超长  →  多答案多行（同一标准问，不同答案内容）
平台超长  →  答案超限内容列（G 列，语音场景留空）
```

### 9.5 导出前校验

| 校验项 | 规则 | 失败处理 |
|--------|------|----------|
| 标准问字数 | ≤200 | 截断 + warning |
| 答案字数 | ≤ maxAnswerLength | 多轮拆分 |
| 所属目录 | 必须含 `/` | 自动补全 |
| 相似问字数 | ≤200 | 截断 |
| 每标准问答案数 | ≤50 | 截断 |
| 跨 Sheet 一致性 | 标准问完全匹配 | 阻止导出 |
| 文件大小 | ≤5 MB | 自动拆分多个文件 |
| Sheet 行数 | ≤10,000 | warning |

## 10. 质量审核体系

### 10.1 两层审核架构

```
Phase 3 语义审核（LLM）     →  去重、冲突、目录规范
Phase 7 格式审核（本地规则） →  字数、目录格式、跨 Sheet 一致性
```

### 10.2 语义审核（Phase 3）

| 检查项 | 处理 |
|--------|------|
| 语义重复 | 合并 |
| 目录不一致 | 规范化 |
| 答案冲突 | `conflict: true`，人工裁决 |
| 无效条目 | 删除 |
| 标准问过长 | 精简 |

### 10.3 格式审核（Phase 7）

| 检查项 | 处理 |
|--------|------|
| 字数超限 | 截断或拆分 |
| 目录缺 `/` | 自动补全 |
| 跨 Sheet 不一致 | 报错 |
| 文件/行数超限 | 拆分或 warning |

### 10.4 UI 审核标记

| 标记 | 含义 | 展示 |
|------|------|------|
| `needsHuman: true` | 敏感/复杂 | 红色 + ⚠️ |
| `conflict: true` | 答案冲突 | 黄色 + 详情 |
| `warnings[]` | 格式警告 | 导出前列表 |

### 10.5 导入后提醒

> 文件导入平台后，请将问答状态设置为「已上线」，大模型问答功能方可生效。
